# 辞書を育てる

LLM は口述のたびには使わない。履歴をまとめて読み、**同じ間違いを機械で直せる形（辞書）に落とす**ためにだけ使う。
アプリ内の「候補」タブは出現回数の偏りで拾う。ここでは回数では拾えない、文脈で正解が分かる誤変換を拾う。

**履歴のテキストは LLM の提供元に送られる。** アプリ本体の「端末の外に出さない」とは別に、利用者が選んで行う操作である。始める前にそのことを一言伝える。

## 手順

1. **書き出す**: `./scripts/dict-grow.py dump [--since 前回の日付] > <scratchpad>/hist.tsv`。前回の日付は `ls ~/sarari/replacements.json.bak-*` の最新から推す
2. **候補を出す**: 300 行ずつに分けてサブエージェント（sonnet）で並列に読ませる。拾うのは「文脈から正解が一意に分かる誤変換」だけで、抜粋と直した形を返させる。件数が数百行なら自分で読んでよい
3. **辞書に落とせるものに絞る**。決めるのはここだけ:
   - **入れる**: 同じ化け方が繰り返す語、または化けた形がそれ自体では普通の語でないもの（`スライプ`・`KitHub`・`リポストリ`）
   - **入れない**: 化けた形が普通の語（`一周`・`石`・`履修`・`オルガン`）、短い英字（`EC`・`Is`・`Es`）。置換は単語境界を見ない部分一致なので、別の文を壊す。前後の語を含めた長い形（`GitHub EC`）なら入れてよい
   - **入れない**: 一度きりの同音異義（`金のため`→`念のため`）。文脈でしか直らないので辞書の守備範囲外
4. **誤爆を確かめる**: 候補を `読み<TAB>置換後` の TSV にして `./scripts/dict-grow.py check <tsv>`。一致した文がすべて狙った誤変換であること、`[既存]` が付いていないことを見る。狙っていない文に当たった候補は外すか、長い形にする
5. **見せてから足す**: 足す表と、入れなかった語とその理由をユーザーに見せる。了承を得たら `./scripts/dict-grow.py apply <tsv>`（バックアップを取ってから末尾に追記する）。アプリはファイルを監視しているので再起動は要らない

## 報告

足したルール数と合計、入れなかった語とその理由、バックアップの場所。`~/sarari/` はリポジトリの外なのでコミットはない。
